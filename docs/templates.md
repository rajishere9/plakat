# Built-in templates: contributor guide

Plakat ships a starter library of templates in [`/templates`](../templates). Every file is an ordinary Plakat document with `kind: "template"` ([document-schema.md §10](./document-schema.md#10-templates-and-slots)), stored as a portable `.plakat.json` file ([§14](./document-schema.md#14-portable-files-plakatjson)). The server loads them all at startup. This guide covers adding a template, the rules a template has to follow, and how the server picks it up.

## Layout of `/templates`

```
templates/
  <category>/<slug>.plakat.json   the templates (the only files the server reads)
  assets/                         source images that templates embed (CC0, generated by placeholders.ts)
  scripts/
    build-templates.ts            generator: builds every template from code (reproducible)
    placeholders.ts               draws the placeholder artwork in assets/
    preview-templates.ts          renders template pages to PNG for a visual check
    lib.ts                        shared helpers (file discovery, asset loading)
  templates.test.ts               validation suite for every template file
  vitest.config.ts, tsconfig.json
```

Current library:

| Category (`template.category`) | Templates |
|---|---|
| `instagram-post` | `quote-card`, `product-launch` |
| `instagram-story` | `event-announcement` |
| `youtube-thumbnail` | `bold-tutorial`, `vlog` |
| `poster` (A4) | `concert-poster`, `cafe-menu` (2 pages) |
| `business-card` | `minimal-us` (US 3.5 × 2 in, front + back), `classic-eu` (EU 85 × 55 mm, front + back) |

## Naming rules

- **Path:** `templates/<category>/<slug>.plakat.json`, exactly one directory deep.
- **`<category>` and `<slug>`** are lowercase kebab-case (`^[a-z0-9]+(?:-[a-z0-9]+)*$`). Reuse an existing category when one fits. A new category is a new gallery filter, so add one only for a genuinely new kind of design. Name format categories after the page format (`instagram-post`, `poster`, `business-card`) and not after a topic. Topics go in `meta.tags`.
- **`template.category`** must equal the directory name.
- **Document `id`** must be unique across the library. The server upserts built-ins **keyed by document id**, so the id is the template's identity: once a template is released, **never change its id**. Changing it would add a duplicate and orphan the old row. The generator uses `tpl_<category>_<slug>`. Files saved from the editor have a random `doc_…` id, which is also fine; just keep it stable from then on.
- **`meta.title`** is the gallery name, in Title case and short ("Quote card", not "Instagram quote card template"). **`meta.description`** is one sentence. **`meta.tags`** are lowercase search words (format, use case, style).

## Path A: design in the editor

1. Create a design with the right page preset and design it. Follow the [font rules](#font-rules) and [asset rules](#asset-rules).
2. Click **Save as template**. This calls `saveAsTemplate()`, which makes a copy with fresh ids. Pick the slots ([slot guidelines](#slot-guidelines)), give each a label, set `maxLength` for text slots, and set the category to the target directory name.
3. Click **Download template file**. The editor bundles every image into `data:` URIs (`bundleAssets()`) and writes canonical JSON (`serializeDocument()`).
4. Save the file as `templates/<category>/<slug>.plakat.json`.
5. Fix the provenance of every asset: set `source` with the license and author (see [asset rules](#asset-rules)). Uploaded images arrive with `provider: "upload"` and no license, and the test suite rejects that.
6. Run the checks:

   ```sh
   npx vitest run templates/
   npx tsx templates/scripts/preview-templates.ts --stress <slug>
   ```

7. Look at the PNGs (see [Previewing](#previewing)), then open a PR.

## Path B: build it in code (generator)

`templates/scripts/build-templates.ts` builds the whole library with the `@plakat/schema` factories. It is the reference for how the built-ins were made, and the easiest way to keep a template reproducible.

1. Copy an existing `defineTemplate({ … })` block and change it:
   - `category`, `slug`, `preset` (a `PresetId` from `PAGE_PRESETS`), `title`, `description`, `tags`;
   - `pages(size)` returns `{ id, name, background, elements }[]`. Use the helpers `text()`, `rect()`, `ellipse()`, `shape()`, `image()`, plus `locked()` for decoration, `grouped()` for groups, and `attach()` to place a child inside a rotated parent. `size` holds the exact (fractional) page size for print presets;
   - `slots` lists `SlotSpec`s, each with a stable `id` (`slot_<name>`), in fill-form order.
2. Use readable, stable ids: `pg_front`, `el_headline`, `slot_headline`. Element, page and slot ids share one namespace (D-17).
3. Images: add a file to `templates/assets/` and register it in `ASSETS` (`loadTemplateAsset(file, name, source?)`). It reads the pixel size from the PNG/JPEG header and embeds the file as a `data:` URI.
4. Run:

   ```sh
   npx tsx templates/scripts/build-templates.ts            # write all files
   npx tsx templates/scripts/build-templates.ts my-slug    # only matching templates
   npx tsx templates/scripts/build-templates.ts --check    # CI: fail if a file is stale
   npx tsx templates/scripts/preview-templates.ts --stress my-slug
   npx vitest run templates/
   ```

The generator turns each design into a template with `convertToTemplate()` and `addSlot()`, renames the minted slot ids to the stable ones, validates the result by round-tripping it through `loadDocument()`, and writes it with `serializeDocument()`. Ids and timestamps are fixed, so the output is byte-for-byte reproducible. If you edit a generated file by hand, the next generator run overwrites your change, so change the code instead. Templates added through Path A are not in the generator and are never touched by it.

## Previewing

```sh
npx tsx templates/scripts/preview-templates.ts [--out DIR] [--fonts DIR] [--width PX] [--stress] [filter ...]
```

The preview renders every page to `<tmp>/plakat-template-previews/<category>__<slug>[.stress].p<N>.png`. It downloads the needed Google Fonts once into `<tmp>/plakat-font-cache`, so it needs network access the first time. `--stress` also renders the template instantiated with **max-length** text in every text slot. Use it to check that long input does not collide with other elements, and lower a slot's `maxLength` or enlarge its box until it holds. The preview is a close approximation built on node-canvas and Konva that follows [render-export-pipeline.md §3](./render-export-pipeline.md). The pixel-exact renderer is `@plakat/renderer`.

## Design guidelines

- **Hierarchy first:** one dominant element (headline, name, photo), one secondary level, then small supporting text. Use at most 2 type families per template, plus an optional script accent.
- **Palette:** 1 background, 1 ink, 1 accent, and at most 1–2 neutrals. Decoration should use neutrals or tints that still work when the accent color slot changes.
- **Margins:** keep at least ~5 % of the short side clear around important content. Instagram stories keep key content out of the top and bottom ~250 px. YouTube thumbnails keep the bottom-right corner free (the timestamp covers it).
- **Print** (posters, cards): keep text at least ~8 px (6 pt) on business cards and keep content inside a ~3 mm safety margin. Bleed is not supported in V1 (schema §3), so avoid full-bleed designs that rely on edge-to-edge printing, or accept a thin white edge.
- **Shapes as decoration:** circles, rings, bars, stars and capsule frames. Lock purely decorative elements (`locked: true`) so that a click selects the content above them.
- **No real people or brands** in placeholder content. Use invented names, handles, domains and quotes.

## Slot guidelines

Slots are the "Use template" fill form (schema §10). Each slot targets one or more elements.

- **What becomes a slot:** every piece of text a user would always change (headline, name, date, contact lines), every photo and logo, and the 1–2 colors that define the look (the accent; sometimes a background, implemented as a full-size locked `rect` because page backgrounds cannot be slots, D-15). Fixed labels ("DATE", "Menu") and decoration stay unslotted. Users can still edit them after instantiation.
- **Labels:** short, in sentence case, describing the content ("Event name", "Accent color"), never the element ("Text 3"). Use `description` for guidance such as "One dish per line" or "Portrait photos work best".
- **Order:** most important first (headline/name, main photo, …), colors last.
- **`required`:** set it only for the fields that make the template meaningful (headline, main photo). Enforcement is opt-in (`enforceRequired`).
- **Text `maxLength`:** always set it, and choose it with `--stress` so that the longest allowed input still fits the layout. The placeholder must itself respect `maxLength`. **`multiline: false`** for one-line fields (names, prices, labels), **`true`** when line breaks are part of the design ("Summer\nSounds").
- **Multi-target slots** are encouraged when one value appears twice: the café name on the cover and on the menu page, the company on both card sides, one accent color across many shapes.
- **Image slots:** `fit: "cover"` for photos, `"contain"` for logos. Place logos on a transparent background.
- **Color slots:** `property: "fill"` targets shapes or text, `"stroke"` targets shapes (e.g. a frame). Give a `palette` of 3–5 harmonious swatches; the first one is the template's own color.
- **Slot ids** are stable and readable (`slot_headline`). Never reuse one id for a different meaning in a released template.

## Asset rules

- **Portable only:** every `asset.src` is a `data:` URI (`isPortable(doc) === true`). Never use remote URLs or server paths.
- **Size budget:** each embedded image ≤ ~60 KB (the test hard limit is 80 KB), and each file < 1.5 MB. Use JPEG (quality ~0.8) for photos and gradients, PNG for logos and transparency, at modest resolution (≤ ~1280 px on the long side). The user replaces placeholders anyway.
- **`width`/`height`** must be the image's real pixel size (crops live in that space, D-19). `loadTemplateAsset()` reads it from the file header. Do not upscale.
- **Licensing:** use only **your own work or CC0** images. Do not use CC BY, CC BY-SA or "free for commercial use" stock, and do not use AI output of unclear provenance or anything with recognizable people, logos or trademarks. Record provenance in `asset.source`:

  ```json
  "source": {
    "provider": "plakat-templates", "externalId": null, "pageUrl": null,
    "author": "Plakat contributors", "license": "CC0-1.0",
    "licenseUrl": "https://creativecommons.org/publicdomain/zero/1.0/",
    "attribution": "Placeholder artwork by Plakat contributors (CC0 1.0)"
  }
  ```

  For a CC0 photo from elsewhere, set `provider` to the site, `pageUrl` to the original page, and `author` to the creator. The test requires `license` and `author` (or `attribution`) on every asset.
- The bundled placeholders in `templates/assets/` are drawn procedurally by `placeholders.ts` (seeded, CC0). Reuse them freely.
- Every asset in a template must be referenced by an element or background. The test rejects unused registry entries.

## Font rules

- Use only families from `GOOGLE_FONTS_CATALOG` (`packages/schema/src/font-catalog.ts`), and only weights and styles that the catalog lists for that family (`hasFontVariant()`). Example: `Bebas Neue`, `Anton` and `Lobster` are 400 only, `Oswald` has no italics, and `Playfair Display` starts at 400. The test checks every text element.
- If you need a family that is not in the catalog, first add it to the catalog in a separate PR that touches `@plakat/schema`, with exact weight data.
- Fonts are not embedded (D-13). `doc.fonts` is derived and kept in sync by `serializeDocument()`.

## What the tests check (`templates/templates.test.ts`)

For every `templates/**/*.plakat.json`:

- the file is at `templates/<category>/<slug>.plakat.json`, kebab-case, and `template.category === <category>`;
- `loadDocument()` succeeds, `kind === "template"`, and the file is byte-identical to `serializeDocument(doc)` (canonical, fonts cache in sync);
- title, description and at least one tag are present, and document ids are unique across the library;
- `isPortable()`, the file is < 1.5 MB, and each asset is ≤ 80 KB;
- every asset has license provenance, and no asset is unused;
- there is at least one slot, every slot has a label, every target exists, and text placeholders respect `maxLength`/`multiline`;
- every text element uses a catalogued font family and variant;
- `instantiateTemplate()` works without fills, and with a fill for every slot (with `enforceRequired`), and every target receives its fill.

Run them with `npx vitest run templates/`. The trailing slash matters: without it, the path filter also matches `packages/schema/src/templates.test.ts`.

## PR checklist

- [ ] File at `templates/<category>/<slug>.plakat.json` with a stable, unique `id`
- [ ] Title, one-sentence description and tags filled in, and `template.category` = directory
- [ ] Slots: labels, order, `maxLength` on every text slot, sensible `required`, color palettes
- [ ] `preview-templates.ts --stress` output checked by eye; attach the PNGs to the PR
- [ ] Only catalogued fonts and variants
- [ ] Images are `data:` URIs, each ≤ ~60 KB, own work or CC0, with `source` filled in
- [ ] No real people, brands or trademarks in placeholder content
- [ ] `npx vitest run templates/` is green (and `build-templates.ts --check` if you used the generator)

## How the server seeds built-ins

On startup, the server (`apps/server`) scans `TEMPLATES_DIR` (default `<repo>/templates`) recursively for `*.plakat.json`. It validates each file with `loadDocument()` and **upserts it as a built-in row keyed by the document `id`** (`builtIn: true`). Built-ins are therefore re-synced from disk on every start: edit a file, restart the server, and the template is updated. Built-ins appear in `GET /api/templates` (filter with `?category=<category>&q=<text>`; `category` is `template.category`), cannot be deleted (`DELETE /api/templates/:id` answers 403), and can be downloaded again as a portable file with `GET /api/templates/:id/file`. Their `thumbnailUrl` may be `null` until a thumbnail has been uploaded (`PUT /api/templates/:id/thumbnail`). Users import their own template files with `POST /api/templates/import`. Only `*.plakat.json` files are seeded, so `templates/assets/` and `templates/scripts/` are ignored. Check `apps/server` for the exact handling of invalid files.
